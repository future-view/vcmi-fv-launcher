# ADR 0006：守卫分级——共存优先于硬阻断

- 状态：已采纳
- 相关：[realms](../features/realms.zh-CN.md) §11、[error-codes](../reference/error-codes.zh-CN.md) §4

## 背景

启动器有多处守卫（VCMI 进程守卫、依赖守卫、冲突守卫、自检）。早期倾向于"有问题就阻断"，结果把用户锁在门外。

## 决策

守卫**分级**：只有"会造成数据损坏"才阻断；"改动可能不生效"一律**放行 + 提示**。

## 理由

用户在启动器里遇到阻断时没有自救手段；而"改动不生效"是可恢复的，提示即可。

## 后果

- 进程守卫只阻断会改写 `dirs.json` 的操作（激活 / 停用 / 地图阀门 / 领域模组变更），**不阻断只读浏览**；
- 激活失败、自检失败都只记录日志并提示，仍进入领域；
- 依赖 / 冲突未满足不阻断保存，只在 UI 标缺陷。
